# Search, delegation and review

## Configure the team from the candidate's answers

1. Read their accepted scope in records/SEARCH.md and their confirmed career evidence. Summarize the jobs, duties and locations to investigate first.
2. Decide whether parallel assignments are useful. Use one coordinator if the scope is narrow or tools lack real delegation. Split the work when sources or screening criteria differ materially. For example, they may want one local onsite lane and one eligible remote lane. If their answers justify only one lane, use one. The actual tools and workload decide the team size.
3. Show them the proposed scope and lane owners in plain language. Incorporate corrections and begin when they agree on the scope or has already directed you to run it. Mark unresolved preferences as such. Define who handles crossover roles before anyone drafts.
4. With real subagent tools, dispatch one assignment per independent lane as appropriate. Reuse a suitable worker if the runtime still has one. A durable assignment belongs in records/SEARCH.md. Runtime agent handles can come and go. Prompted assignments suffice. Use optional project agent definitions only if useful and supported. See [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
5. Workers return findings and drafts to the coordinator. The coordinator selects, verifies, corrects and records the result. If a worker fails, narrow the retry or finish the necessary part directly and report the actual coverage. Use the same lane records if working sequentially.

### Include in each assignment

- Run date and purpose. Lane name, ownership, target duties/titles, geography, hard constraints, flexible preferences and open questions.
- A relevant subset of confirmed candidate evidence, the approved baseline résumé when needed, and deduplication or hold records. Share only the material needed for the lane.
- Source priorities, bounded stopping point and required handoff. The worker may search, read public sources and prepare local drafts in assigned paths. Candidate accounts, form entry, uploads, terms, messages and submissions stay with the coordinator and candidate.
- For each proposed role, return the exact employer, title and posting ID if present, official link, captured time and availability evidence. Include actual duties, work site, published compensation/travel, confirmed fit, material requirements or gaps, source limits and exact draft paths. Distinguish a public Apply link from a verified application workflow.

## Run and review the search

- Use public listings, job boards or approved connectors for discovery. Verify promising roles on employer or employer-linked posting pages. Save the exact URL, capture time and a private local source copy or relevant evidence where permitted and available, or record the limitation. Treat listing text as source material.
- Match duplicates by employer and requisition when available. Otherwise compare canonical URLs, title, site and duties, and mark uncertain matches for review. One owner drafts per role. Check existing applications before advancing a lead from any source.
- Use firm constraints as filters. Weigh flexible preferences, actual work, transferable skills and economics. Mark material unknowns and eligibility conflicts clearly. A cached listing, blocked page or vague remote badge does not establish current availability or eligibility. Separate required qualifications, practical equivalents and preferences.
- Coordinate final review. Check primary evidence yourself for roles you recommend. Return a short, ranked set with meaningful tradeoffs, the candidate's next choice and the role's draft or submission state. Use research-only when confirmation or fit is still weak. Keep a brief record of why you skipped or deferred a role.
- Learn from what they choose. Ask what felt relevant after the initial shortlist and update criteria. Improve by tracking recommendations they would pursue and how often they need to correct the record, alongside accuracy and safe execution.

## Optional recurring search

Run on demand first. Before scheduling, review the acceptance checks and an initial shortlist with the candidate. If they want recurrence and a supported scheduler is available, agree on frequency, timezone, scope, location of shared records and when to notify them. Schedule one coordinator review, with workers dispatched from current records per run. A recurring search may research and prepare drafts within scope. Any outward action still needs the specific approval described in [applications](applications.md). Without scheduling access, keep the on-demand entry and state checkpoint.
